# OGC-SAGE 초보자 입문서 설계

## 목적

`docs/OGC2026_Competition_Algorithm_Design.md`의 OGC-SAGE 설계를 바꾸지 않고, 메타휴리스틱에는 익숙하지만 OGC 보관·크레인 도메인에는 처음인 독자가 이 설계가 선택된 근거와 각 단계의 역할을 이해하도록 돕는다.

## 독자와 읽기 경험

- 독자는 LNS, MIP, 수리휴리스틱의 기본 개념을 안다.
- 독자는 block, bay, layer, 크레인 이동, 공식 검증기의 재생 규칙을 모른다.
- 독자는 짧은 번역이나 요약보다 작은 사례와 설계 선택의 이유를 따라가며 읽기를 원한다.

## 산출물과 경계

- 새 파일 `docs/OGC2026_Competition_Algorithm_Design_ko_beginners_guide.md`를 추가한다.
- 기존 `OGC2026_Competition_Algorithm_Design_ko.md`(직역본)와 `OGC2026_Competition_Algorithm_Design_ko_readable.md`(가독성 개선본)는 수정하지 않는다.
- 원문과 `baseline/utils.py`가 정확성의 기준이다. 새 입문서는 새로운 알고리즘, 성능 수치, 또는 제약을 주장하지 않는다.
- 새 문서는 한국어 Markdown으로 작성한다. 원문의 모든 수식·실험 재현 절차·세부 파라미터를 반복하지 않고, 필요한 경우 원문으로 연결한다.

## 문서 구조

1. **한 장으로 보는 OGC-SAGE**: 이 솔버가 무엇을 보장하고 무엇을 개선하는지, 전체 흐름을 먼저 제시한다.
2. **왜 이 문제가 보통의 일정 문제보다 어려운가**: 공간·층·크레인 이동·시간·bay 배정이 얽히는 작은 창고 사례를 설명한다.
3. **성공의 정의와 안전 우선 원칙**: `-1` 위험, 검증된 incumbent, anytime 동작을 설명한다.
4. **설계의 세 층**: Gurobi 마스터, 정확 기하 생성기, Gurobi 개선 루프의 책임과 전달물을 설명한다.
5. **쌍의 네 상태를 직관으로 이해하기**: FREE, 두 outer 상태, SEPARATE가 시간 관계를 어떻게 제한하는지 사례 중심으로 설명한다.
6. **한 번의 솔버 실행 여정**: P0부터 P6까지 단계별 목적, 산출, 실패 시의 안전한 폴백을 설명한다.
7. **메타휴리스틱이 실제로 들어가는 곳**: 후보 다양화, regret insertion, LNS 파괴·복구, adaptive 선택이 OGC-SAGE에서 맡는 일을 설명한다.
8. **고급 기능을 게이트 뒤에 두는 이유**: 인터록, 병렬화, Gurobi 라이선스·크기 위험을 검증 기준과 함께 정리한다.
9. **용어와 다음 읽기**: 핵심 용어를 복습하고 원문·한국어 직역본·가독성 개선본으로 가는 읽기 경로를 제공한다.

## 문체와 설명 규칙

- 각 절은 “문제 상황 → 설계 결정 → 기대 효과 → 실패해도 안전한 이유” 흐름을 따른다.
- 외래어는 첫 등장 시 쉬운 한국어 설명과 함께 제시하고 이후에는 한 용어로 일관되게 쓴다.
- `G(i|k)`, indicator constraint, suffix union 같은 구현 표기는 필요성을 설명할 때만 짧게 소개하고, 수식 전개는 원문에 위임한다.
- 네 상태 모델은 정확한 시간 부등식을 외우게 하기보다 “서로 방해하지 않음 / 한쪽이 바깥에서 다른 쪽을 감쌈 / 반드시 교대해야 함”이라는 물리적 의미를 먼저 설명한다.
- 공개 학습 데이터와 로컬 프로브의 수치는 설계 선택의 근거임을 밝히되, 숨은 인스턴스의 성능 보장처럼 표현하지 않는다.

## 완료 판단

문서만 읽고 다음을 설명할 수 있으면 완료로 본다.

1. 왜 OGC-SAGE가 단일 거대 MIP나 탐욕 알고리즘 확장이 아닌 세 층 구조인가?
2. 왜 optional Gurobi 호출 전에 검증된 incumbent가 필요한가?
3. 네 상태 쌍 모델은 공간 관계를 어떤 시간 선택으로 바꾸는가?
4. 생성기와 LNS가 각각 무엇을 해결하며, 둘 다 정확 기하 검증을 어떻게 존중하는가?
5. 인터록과 병렬화가 기본 기능이 아니라 게이트된 기능인 이유는 무엇인가?

## 검증

- 원문과 대조해 솔버 단계, 네 상태 의미, 안전 폴백, 프로브의 주장 범위가 달라지지 않았는지 확인한다.
- 새 문서에서 참조하는 세 개의 관련 문서 링크가 모두 유효한지 확인한다.
- Markdown 제목 구조, 중복 제목, 미완성 표기를 검사한다.

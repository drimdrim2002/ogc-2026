# 초보자를 위한 솔버 설계 입문서 설계

## 목적

`docs/fable/solver-design.md`의 정확한 설계를 바꾸지 않고, 메타휴리스틱에는 익숙하지만 OGC 보관·크레인 도메인은 처음인 독자가 설계의 이유와 전체 흐름을 이해할 수 있게 한다.

## 독자와 읽기 경험

- 독자는 메타휴리스틱, 지역 탐색, 수리 최적화의 기본 개념을 안다.
- 독자는 OGC의 블록·bay·다층 이동 제약과 공식 체커의 재생 규칙은 모른다.
- 독자는 짧은 요약보다 개념 사이의 인과관계와 작은 예시를 꼼꼼히 읽는 방식을 선호한다.

## 산출물과 경계

- 새 파일 `docs/fable/solver-design-beginners-guide.md`를 추가한다.
- 기존 `solver-design-for-everyone.md`는 빠른 개요로 유지한다.
- `solver-design.md`와 `baseline/utils.py`는 의미론과 구현 판단의 단일 기준으로 유지한다. 새 문서는 규칙을 새로 정의하거나 원문과 충돌하는 단순화를 하지 않는다.
- 새 문서는 한국어 Markdown으로 작성한다. 실행 코드, 알고리즘 파라미터, 체커 줄번호의 나열은 포함하지 않는다.

## 문서 구조

1. **어떤 문제를 푸는가**: bay를 창고 구역, 블록을 여러 층을 가진 화물로 설명하고, 공간·이동·시간 제약이 동시에 필요한 이유를 작은 사례로 보여 준다.
2. **무엇을 좋은 해라고 부르는가**: 지각, bay 부하 불균형, 선호 bay 손실이라는 세 비용과 가중치에 따른 교환을 설명한다.
3. **왜 안전한 해가 먼저인가**: `-1` 위험, T0, incumbent, 전체 검증 후 교체라는 안전 프로토콜을 설명한다.
4. **설계를 단순하게 만드는 세 통찰**: bay 간 독립성, 위치가 직접 목적함수에 기여하지 않는 점, 블록 쌍 중심의 검증을 각각 직관과 효과로 해설한다.
5. **솔버의 한 번의 여정**: 전처리 → 안전망 → 초기 배정·배치 → 일정 정밀화 → LNS → 반환을 단계별 입력·산출·실패 시 행동과 함께 설명한다.
6. **헷갈리기 쉬운 규칙**: 접촉과 겹침, 같은 날 교대, 최소 체류일, 인터락을 시간선·작은 예시로 설명한다.
7. **고급 기능을 왜 늦게 켜는가**: Gurobi/CP-SAT, 병렬화, 인터락의 기대 이득과 오류 위험을 게이트 방식으로 정리한다.
8. **읽은 뒤의 지도**: 용어 요약, 원문 상세 설계서·10분 개요·구현 계획서로 이어지는 다음 읽기 경로를 제공한다.

## 문체와 설명 규칙

- 처음 등장하는 도메인 용어는 즉시 한국어로 풀고, 필요할 때만 영문 표기를 괄호 안에 둔다.
- 각 절은 “무엇인가 → 왜 필요한가 → 솔버에서 어떻게 쓰는가” 순서를 따른다.
- 메타휴리스틱 용어는 독자가 안다고 가정하되, OGC에서 그 기법이 맡는 구체적 역할을 명시한다.
- 수학적 증명, 정확한 임계값, 체커 코드 근거는 상세 설계서로 위임하되, 독자가 왜 그 결론을 믿어야 하는지는 일상어로 설명한다.
- 예시는 설명을 위한 것이며 새 규칙을 만들지 않는다. 정확한 판단이 필요할 때는 상세 설계서를 우선하도록 명시한다.

## 완료 판단

다음 질문에 문서만으로 답할 수 있으면 완료로 본다.

1. 왜 솔버가 최고 품질 탐색 전에 검증된 T0 해를 만드는가?
2. 어떤 결정은 bay 배정에서, 어떤 결정은 bay 내부 배치·일정에서 다루는가?
3. 정확한 기하 검증과 빠른 후보 탐색은 어떻게 공존하는가?
4. LNS와 수리 최적화는 각각 어느 단계에서 무엇을 개선하는가?
5. 인터락·병렬화·exact backend가 기본 경로가 아니라 게이트된 고급 기능인 이유는 무엇인가?

## 검증

- 원문 상세 설계서의 핵심 주장과 대조하여 사실 관계가 바뀌지 않았는지 확인한다.
- 문서의 내부 링크와 상대 링크를 확인한다.
- Markdown 제목 구조와 금지된 미완성 표기(TODO, TBD)를 검사한다.

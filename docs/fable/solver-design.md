## 0. 설계 목표: 채점 함수에서 역산한 원칙

대회 채점(정의서 §5.5): 인스턴스별로 infeasible/timeout/crash면 **−1점**, feasible이면 `R − nb` (R = 평가 팀 수, nb = 그 인스턴스에서 **엄격히 더 좋은** objective를 낸 팀 수). 총점은 전 인스턴스 합. 여기서 네 가지 설계 원칙이 즉시 나온다.

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **절대 −1 금지가 최우선이다.** 한 인스턴스의 −1은 그 인스턴스에서 얻을 수 있었던 ~R점을 통째로 잃는다. 어떤 개선 탐색도 "검증된 feasible 해를 이미 손에 쥔 상태"에서만 수행한다 | 정의서 §5.3, §5.5 |
| P2 | **미공개 timelimit에 비례해 동작해야 한다.** 시간제한은 "수 분~30분"이며 `algorithm(prob_info, timelimit)`의 파라미터로 전달된다. 고정 파이프라인은 큰 예산을 버린다. anytime 구조(언제 끊어도 최선의 검증된 해 반환)가 필수다 | 정의서 §5.4, §6.2 |
| P3 | **엄격히 더 좋으면 순위가 오른다.** objective는 float이고 동률은 nb에 안 잡히므로, 마지막 한 단위의 개선도 순위 가치가 있다. 정확한(근사 아닌) delta 평가와 마무리 미세 최적화가 점수다 | 정의서 §5.5, utils.py:1421 |
| P4 | **숨은 인스턴스는 일반화를 보상한다.** 보이는 인스턴스에 대한 하드코딩 금지. 모든 임계값은 인스턴스 데이터(가중치, 규모, 혼잡도)에서 유도한다 | 정의서 §3, §7.3 |

부가 사실: 서버는 4코어(400%)/16GB/인터넷 없음, shapely 2.1.2·OR-Tools 9.15·numpy 계열과 gurobipy/xpress가 사용 가능하다(정의서 §5.4, §6.1). gurobipy/xpress는 지원 패키지지만, 최종 심사의 코드 공개 적격성·런타임 실패 표면·구현 단순성을 고려해 기본 수리 컴포넌트는 **CP-SAT(OR-Tools)** 로 제한한다.

## 1. 검증 원칙

1. 체커가 유일한 의미론 권위다. 정의서와 체커가 다르게 읽히면 체커가 이긴다(서버는 `utils.py`를 덮어써 실행한다 — 정의서 §5.1).
2. 방향성 규칙(≤/≥, 먼저/나중, 위/아래)은 §2의 진리표로 유도하고, 구현 전에 `check_feasibility`를 오라클로 쓰는 단위 테스트로 고정한다.
3. 내부 objective/delta 계산은 체커와의 패리티 테스트를 의무로 갖고, 해 수용의 권위는 항상 `check_feasibility` 반환값이다.
4. 기하 판정의 권위는 shapely(체커 경로) 단일이다. 자체 기하는 (i) 정수 오프셋 키의 **판정값 캐시**(근사가 아니라 저장), (ii) **보수적 프리필터**(불확실하면 반드시 정확 판정으로 폴백) 두 형태만 허용한다.

## 2. 문제의 수학적 구조 (체커에서 유도한 정리들)

### 2.1 결정 변수와 기본 제약

블록 i마다: bay `b_i`, 정수 위치 `(x_i, y_i)`, orientation `o_i`, 정수 진입일 `a_i`, 정수 반출일 `e_i`. 점유 구간은 반개구간 `[a_i, e_i)`.

- `a_i ≥ R_i`, `e_i − a_i ≥ P_i` (허용오차 1e-6, utils.py:1123-1131). **e는 자유 변수다** — `e = a + P`는 제약이 아니라 선택이고, 체커 재생 의미론 때문에 `P=0`에서는 `e=a+1` 이상이 필요하다(정의서 §2.6, §2.3).
- 경계: 체커의 포함 판정은 블록 전 레이어 AABB가 `[0,W]×[0,H]` 안에 있는지다(utils.py:252-266, 1244-1251; 경계 접촉 허용). bay가 축정렬 직사각형이므로 이는 다각형 포함과 동치다.
- 좌표는 `int(round())`로 반올림 후 검사된다(utils.py:1151-1153) — 솔버는 처음부터 정수만 출력한다.
- 존재 집합 의미론: **Stage 2**(진입 시) `a_k ≤ t < e_k` — 하한 포함(utils.py:1177). **Stage 3**(반출 시) `a_k < t < e_k` — 양끝 배제(utils.py:1217). **Stage 4** 쌍별 시간겹침 `a1 < e2 and a2 < e1`(utils.py:1156-1158). **Stage 5** 날짜 오름차순 재생, 같은 날짜에서 EXIT이 ENTRY보다 먼저(utils.py:1293-1302), 같은 타입 내에서는 **나열된 리스트 순서대로** 라이브 present-set에 대해 순차 검사(utils.py:1304-1382).
- 크레인 스윕: 이동 블록의 레이어 k는 존재 블록의 레이어 `j ≥ k`와 내부 겹침(area > 0) 금지 — 진입(utils.py:703)·반출(utils.py:799) 동일. 정적 충돌은 같은 레벨끼리만, `min(K1,K2)`까지(utils.py:521). 모든 판정은 shapely `buffer(0)` 복구(utils.py:187-190) 후 엄격한 `area > 0`(utils.py:535, 713, 809)이며 **경계 접촉은 합법**이다.

### 2.2 목적함수 분해 정리

`objective = w1·Z1 + w2·Z2 + w3·Z3`, 전부 float, 내림 없음(utils.py:1388-1421).

- `Z1 = Σ max(0, e_i − D_i)` — **exit 날짜만의 함수** (utils.py:1402).
- `Z2 = max_{j≠j'} |u_j·L_j − u_j'·L_j'|` = 가중 부하의 **range**(max − min), `u_j = 평균면적/면적_j`, 빈 bay도 L=0으로 참여 — **bay 할당만의 함수** (utils.py:1409-1419). 따름정리: bay가 2개 이상인데 한 bay를 비우면 `Z2 = max_j u_j·L_j`로 커진다. 고-w2 인스턴스에서는 전 bay 분산이 필수다.
- `Z3 = Σ (S_i^max − S_i,b_i)` — **bay 할당만의 함수** (utils.py:1404-1405).

**귀결(설계의 근간)**: 위치·방향은 objective에 **한 푼도 직접 기여하지 않는다**. 기하는 순수한 feasibility 자원이며, "어느 bay에서 어떤 진입/반출 날짜가 달성 가능한가"를 결정할 뿐이다. 그러므로:

1. **상위 레벨(할당)**: `b_i` 선택 → Z2+Z3가 닫힌 식으로 확정되고, 각 bay의 블록 집합이 확정된다.
2. **하위 레벨(bay별 스케줄링+패킹)**: bay 간 상호작용은 전혀 없다(체커의 모든 검사가 bay 단위 — utils.py:1168-1273, 1289). bay별로 독립적으로 Σ tardiness를 최소화하면 Z1이 최소화된다.

이 2-레벨 분해는 휴리스틱이 아니라 **정확한** 구조다.

### 2.3 쌍-분해 정리

체커의 feasibility는 (i) 블록 단항 조건(Stage 1 타이밍, 경계)과 (ii) 같은 bay 블록 **쌍** 조건(Stage 2/3/4/5의 장애물·충돌 기록은 전부 특정 쌍에 귀속됨, utils.py:1179-1194, 1219-1228, 1260-1273, 1339-1382)의 논리곱이다. 따라서:

- 해의 일부만 바꿀 때, **바뀐 블록이 관여하는 쌍 + 바뀐 블록의 단항 조건**만 재검사하면 전체 feasibility가 정확히 결정된다(표적 재검증 — 근사가 아님).
- 비-인터락 쌍 조건은 CP-SAT 분리 제약(disjunction)으로 정확히 옮겨진다(§4.4). 인터락 쌍은 중첩 시간 제약과 같은 날 EXIT 순서가 추가로 필요하므로 별도 게이트에서만 다룬다.

### 2.4 쌍 실행가능성 삼분법 (feasibility 이론의 전부)

같은 bay의 블록 쌍 (i, j)가 공존 가능/불가능한 조건은 정확히 다음 세 갈래다. `U_i` = 배치된 orientation의 전 레이어 합집합(union footprint) 다각형.

**갈래 1 — 시간 분리**: `e_i ≤ a_j` 또는 `e_j ≤ a_i` (등호 허용). 이때 기하는 무관하다.
근거: Stage 4는 겹치는 구간만 검사(utils.py:1263-1265). `e_i = a_j`(같은 날 손바뀜)도 안전하다: Stage 2는 상한이 엄격(`t < e_k`)이라 떠나는 블록을 세지 않고(utils.py:1177), Stage 3는 하한이 엄격이라 들어오는 블록을 세지 않으며(utils.py:1217), Stage 5는 같은 날짜에서 EXIT을 먼저 처리해 present-set에서 제거한 뒤 ENTRY를 검사한다(utils.py:1357-1382 → 1330-1355). **같은 날 손바뀜은 합법이고 밀도상 공짜다** — 분리 제약에 `<`가 아니라 `≤`를 쓰는 것이 맞다.

**갈래 2 — union 서로소 (비-인터락)**: 공존하되 `area(U_i ∩ U_j) = 0`.
**정리**: 이 경우 모든 시점·모든 같은 날 나열 순서에서 이 쌍의 모든 체커 술어가 통과한다.
증명: 모든 검사는 어떤 레이어 쌍의 `area(A_k ∩ B_j) > 0`을 요구하는데, `A_k ⊆ U_A`, `B_j ⊆ U_B`이므로 교집합 면적이 0이다. Stage 5 재생의 장애물 술어도 동일 술어다. ∎
역도 유용하다: `area(U_i ∩ U_j) > 0`이면 어떤 레이어 쌍 (k, j)가 겹치고, k ≤ j로 잡으면 그 방향의 이동이 막힌다. 따름정리: **union이 겹치는 쌍은 같은 날 동시 진입이 불가능하다**(Stage 2가 동시 진입자를 존재로 간주하므로 — `a_k ≤ t`, utils.py:1177 — 나열 순서로 구제 불능).

**갈래 3 — 인터락 (층 엇갈림 공존)**: 공존하고 `area(U_i ∩ U_j) > 0`이지만 같은 레벨 레이어끼리는 서로소(Stage 4 통과). 이때 방향 술어를 정의한다:
`OBS(X; Y) := ∃ k ≤ j : area(X_k ∩ Y_j) > 0` — "Y가 존재할 때 X의 수직 이동이 막힌다".
쌍이 공존 가능하려면 한 방향만 막혀야 한다(양방향이면 어느 쪽도 나갈 수 없어 공존 불가). `OBS(host; guest)`만 참이라 하자(guest가 host 위에 걸쳐 있음). **진리표**:

| 사건 | 판정 | 근거 |
|---|---|---|
| host가 guest 존재 중 진입/반출 | 불가 | 동일 술어 `OBS(host;guest)` → Stage 2/3/5 |
| guest가 host 존재 중 진입/반출 | 가능 | `OBS(guest;host)` = false |
| 진입 순서 | **`a_host < a_guest` (strict)** | 같은 날 불가: Stage 2 하한 포함(utils.py:1177) |
| 반출 순서 | **`e_guest ≤ e_host`** | Stage 3 양끝 배제라 등호 허용(utils.py:1217) |
| `e_guest = e_host`인 날 | EXIT 리스트에서 **guest 먼저** | Stage 5가 리스트 순서로 재생(utils.py:1364-1382) |

즉 guest의 체류는 host의 체류에 **중첩(nested)** 된다. host의 최소 반출일 `a_host + P_host`가 `e_guest`보다 이르면 **host의 exit 연장이 필요**하다 — e가 자유 변수여야 하는 이유이며, `e_host ≤ D_host`인 한 연장 비용은 0이다.

이 삼분법이 이 문제의 feasibility 이론 전부다. 어떤 쌍도 세 갈래 중 하나를 만족해야 하고, 각 갈래의 조건은 위처럼 닫힌 형태다.

### 2.5 exit 최소성의 정확한 범위

**정리(비-인터락 영역 국소 지배성)**: 모든 공존 쌍이 갈래 1·2뿐인 해에서, 임의 블록의 e를 `a + max(P, 1)`로 줄여도 feasibility가 유지되고 Z1은 약하게 감소한다.
증명: 구간 축소는 갈래 1 쌍을 갈래 1로 유지하고(분리가 강해질 뿐), 갈래 2 쌍은 시간과 무관하다. Z1은 e에 단조. ∎
**전역적으로는 성립하지 않는다**: 갈래 3의 host는 `e_host ≥ e_guest`가 필요하다. 그러므로 "exit = entry + dwell"은 비-인터락 모드의 내부 규약으로만 쓰고, 인터락과 수리(반출 차단 해소)에서는 e 연장을 1급 레버로 쓴다.

### 2.6 엣지 케이스 카탈로그 (체커에서 직접 유도)

| 케이스 | 규칙 | 근거 |

| `P_i = 0` | 그래도 **체류 ≥ 1일** 필요. `e = a`면 같은 날 EXIT이 ENTRY보다 먼저 처리되어 "not present" 위반 | utils.py:1293-1302, 1357-1363 |

## 3. 왜 이 설계가 이기는가 (순위 레버)

각 레버는 "경쟁자 대비 순위를 올리는 독립 요인"이며, §6 로드맵의 단계와 1:1로 대응한다.

1. **−1 제로 (S0)**: 항상-유효 incumbent 프로토콜(§4.1) + 예산 관리자 + 전역 예외 방어. 숨은 인스턴스·타임아웃에서 −1을 맞는 팀 대비 무상 순위 이득. 이것 하나가 가장 값싸고 확실한 점수원이다.
2. **탐색 처리량 (S1)**: §2.4 삼분법 덕에 배치 후보 검사가 "AABB 일괄 → union 교차 1회"로 줄고(비-인터락 후보에서는 크레인 검사 자체가 소거됨), 정수 오프셋 판정 캐시로 반복 비용을 줄인다. 실제 배율은 S0/S1 마이크로벤치로 검증한다.
3. **layout당 스케줄 최적성 (S2)**: 비-인터락 위치를 고정하면 남는 문제는 "union 겹침 쌍의 시간 분리 + release + tardiness 최소화"라는 **disjunctive 스케줄링**이고, CP-SAT가 강한 후보 컴포넌트다(§4.4). 휴리스틱만 쓰는 팀이 남기는 Z1을 회수한다는 주장은 S2 게이트에서 실측으로 입증한다.
4. **anytime 확장 (S3)**: LNS(destroy-repair) + 주기적 retiming으로 5분·30분 예산을 실제 개선으로 전환. 60초용 고정 파이프라인 팀과의 격차가 큰 timelimit에서 벌어진다.
5. **가중치 적응 (S4)**: Z2/Z3는 닫힌 식이므로 bay-이동/스왑의 이득이 정확히 계산된다. 환율(w1 : w3·ΔS : w2·Δrange)을 읽고 인스턴스마다 다른 지점을 공략한다. 예시 가중치(26667/10/300)에서 선호도 최대 손실(ΔS=100)은 지각 1일과 같은 자릿수다 — 이 트레이드는 인스턴스마다 다르게 갈린다(정의서 §2.7).
6. **인터락 보너스 (S6, 게이트)**: 밀집 인스턴스에서 갈래 3을 쓰는 팀은 드물다(정확히 구현하기 어렵기 때문). 진리표+테스트로 안전하게 켜면 남들이 못 줍는 점수를 줍는다. 단, 기본 off이며 게이트를 통과할 때만.
7. **4코어 활용**: 1차로 CP-SAT `num_search_workers=4`(프로세스 취급 불필요, 안전), 2차로 멀티프로세스 포트폴리오(S5, 게이트).

## 4. 솔버 아키텍처

```text
algorithm(prob_info, timelimit)
 ├─ P0 전처리      : 파싱, 기하 사전계산, fit 행렬, 환율표, 예산 계획
 ├─ P0' 안전망     : T0(순차 단독 배치) 생성 → check_feasibility → incumbent 등록
 ├─ P1 할당        : Z2/Z3 + 혼잡도 근사를 반영한 초기 bay 할당
 ├─ P2 구성        : bay별 삽입식 constructor (비-인터락, 다중 프로파일)
 ├─ P2' 검증/등록  : full check → incumbent 교체
 ├─ P3 개선 루프   : [CP-SAT retiming ↔ LNS destroy-repair ↔ bay-move] (남은 예산 전부)
 │                    수용 후보만 full check → incumbent 교체 (원자적)
 └─ P4 마무리      : incumbent 반환 (이미 검증·직렬화 완료 상태)
```

### 4.1 항상-유효 incumbent 프로토콜 (P1 원칙의 구현)

- 시작 직후(목표 ~1초, S0에서 실측 재보정)에 T0(모든 블록을 "빈 bay 단독 창"에 순차 배치 — 진입·반출 시 bay가 비어 있으므로 모든 스윕이 자명히 통과)를 만들어 **full check 후** incumbent로 등록한다.
- 이후 모든 단계는 "후보 생성 → 표적 재검증(§2.3, 정확) → 개선이면 full check → 통과 시에만 incumbent 원자 교체"를 지킨다. **검증 안 된 해가 incumbent가 되는 경로는 존재하지 않는다.**
- 최상위는 `try/except`로 감싸고, 어떤 예외든 현재 incumbent를 반환한다. 반환 객체는 항상 미리 직렬화된 operations dict이므로 마감 직전 반환은 O(1)이다.
- 예산: `deadline = start + timelimit − reserve`, `reserve = clamp(0.05·timelimit, 3s, 60s)`. 모든 루프는 협조적으로 deadline을 검사한다. timelimit이 극단적으로 작으면(스트레스: 0.5~5s) P2 이후를 건너뛰고 T0 또는 부분 구성 해를 반환한다.

### 4.2 기하 커널

- **사전계산(인스턴스당 1회)**: (block, orient)별 앵커 정렬된 레이어 목록, 레이어별/전체 AABB, **union footprint 다각형**(`shapely.unary_union` + 필요시 `buffer(0)`), `shapely.prepared` 준비 객체, 면적, 레이어 수. bay별 fit(i, j, o) 행렬.
- **판정 의미론**: 후보 수락 조건은 체커와 동일한 `intersection.area > 0` 기준이다. 빠른 경로: prepared `intersects()`가 False면 즉시 통과(서로소 확정); True면 교차 면적을 계산해 0(접촉)이면 통과. 이렇게 해야 접촉-패킹(합법·고밀도)을 잃지 않는다.
- **판정값 캐시**: 위치가 정수이므로 쌍 판정은 `(shape_i, o_i, shape_j, o_j, dx, dy)`로 완전 결정된다. union-서로소 판정과 OBS 방향 판정을 이 키의 dict(LRU 상한)로 캐시한다. 이는 **오라클 답의 저장**이지 제2 기하 구현이 아니다.
- **AABB 일괄 필터**: bay별 존재 블록의 AABB를 numpy 배열로 유지, 후보당 벡터화 비교로 생존자만 shapely에 보낸다.
- (게이트) 보수적 래스터 프리필터: full-cell/touched-cell 이중 마스크의 3분류(확정충돌/확정자유/불확실→shapely). 프로파일링이 정당화할 때만(S6 이후), 패리티 하니스 불일치 1건 = 도입 중단.

### 4.3 Constructor (P2): 비-인터락 삽입식 구성

우선순위 순서로 블록을 하나씩 시공간에 삽입한다. 블록 i에 대해:

1. **시간 후보** (오름차순, 상한 T개): `dwell_i = max(P_i, 1)`로 두고 `{R_i} ∪ {e_j: 배치된 j} ∪ {a_j − dwell_i: 배치된 j}` 중 `≥ R_i`인 것. (구간 feasibility는 이벤트 경계에서만 변하므로 이 집합이 완전하다 — 반출 직후 시작 또는 진입 직전 종료.)
2. 각 시간 t에서 **공존 집합** O(t) = `[t, t+dwell_i)`와 겹치는 배치 블록들(정렬 이벤트 인덱스로 조회).
3. **위치 후보**: 벽 모서리 + O(t) 블록들의 우측/상단 접촉 앵커, (y, x) 사전식 순서, 상한 K개. 각 앵커에서 AABB 일괄 → union 판정(캐시). **first-fit**: (bay, orient)당 가장 이른 (t, 위치) 하나를 얻으면 중단.
4. (bay, orient)별 후보를 점수로 비교해 확정: 사전식 (tardiness `max(0, t+dwell_i−D_i)`, 공간 점수). 공간 점수는 미래 수용력 보존용 — 접촉 길이 최대화(꼭 맞게), **체류시간 조닝**(오래 머무는 블록은 벽·구석으로, 짧은 블록은 전면으로), 낮은 y 우선.
5. exit는 `a + dwell_i`(§2.5 국소 지배성 + §2.6 `P_i=0` 예외 반영). tardiness가 불가피하면 에스컬레이션: 앵커 확대 → (S6 활성 시) 인터락 시도 → 상위 레벨에 bay-bump 제안 → 지연 수용.

**다중 프로파일 multi-start**: 우선순위 프로파일 {slack 오름차순, EDD, 면적×P 내림차순 우선, 선호도-압력} + 약한 편향 무작위화. timelimit의 ≤10%(상한 30s) 안에서 여러 시작을 돌리고 최선을 P3에 넘긴다.

구성 성능 목표: 300블록 인스턴스에서 **≤ 5초**를 가설로 두고 S0/S1 마이크로벤치로 재보정한다. 후보당 정확 판정 수를 계측 필드로 남긴다.

### 4.4 CP-SAT Retiming (P3의 정밀 무기)

**입력**: 한 bay의 고정된 (위치, 방향) 배치. **출력**: 그 layout이 허용하는 최소 Σ tardiness 스케줄.

- 변수: `a_i ∈ [R_i, H]`, `e_i = a_i + max(P_i, 1)` (비-인터락; 인터락 쌍이 있으면 `e_i ≥ a_i + max(P_i,1)`의 변수로 확장하고 중첩 제약 추가).
- 제약: union 겹침 쌍마다 Bool `b_ij`: `b_ij ⇒ e_i ≤ a_j`, `¬b_ij ⇒ e_j ≤ a_i` (등호 포함 — 같은 날 손바뀜 활용). union 서로소 쌍은 **무제약**.
- 목적: `Σ T_i`, `T_i = max(0, e_i − D_i)` (AddMaxEquality). w1은 bay 내 상수라 생략 가능.
- 워밍: 현재 스케줄을 hint로. `num_search_workers = 4`. 타임박스 `min(5s, 예산 지분)`.
- **never-worse 가드**: 결과가 현재 bay Z1보다 엄격히 좋을 때만 채택, 채택 후 full check. 실패/타임아웃이면 무시.

이 컴포넌트의 정확성 근거는 §2.4 삼분법이다: 비-인터락 layout에서 쌍 제약은 정확히 "시간 분리 또는 union 서로소"이고, 후자는 시간과 무관하므로 시간 최적화가 위 모델과 **동치**다. 수백 구간·수천 disjunction 규모는 CP-SAT의 전형적 스위트스팟이다. 구성 직후 1회 + P3에서 layout이 바뀔 때마다 해당 bay만 재실행.

### 4.5 LNS 개선 루프 (P3)

단일 수용 루프에 이웃(move family)들을 꽂는다. 모든 후보는 표적 재검증(§2.3, 정확) → 개선 시 full check → incumbent 교체.

| 이웃 | 내용 | 표적 성분 |
|---|---|---|
| worst-tardiness reinsert | 지각 기여 상위 + 그 지각을 유발하는 "임계 영역"의 이웃 블록 k개 제거 → constructor로 재삽입 | Z1 |
| congestion-window reinsert | 한 bay의 혼잡 시간창에 걸친 블록들 제거·재삽입 | Z1 |
| random-k | 무작위 소집합 재삽입 (탈출) | 전역 |
| **bay-move / swap** | 환율표로 후보 선별(ΔS 작고 혼잡 bay의 大 블록), 대상 bay에 재삽입 + 두 bay retime, Δ(w2·Z2 + w3·Z3) 닫힌 식 + Z1 실측 | Z2, Z3, Z1 |
| exit-extension unblock | (인터락/수리 상황) 막힌 반출을 방해자 반출 뒤로 지연; `e ≤ D`면 비용 0 | feasibility→Z1 |
| orientation polish | 개별 블록 방향 교체로 공간 확보 | 간접 |
| retime 호출 | 누적 변경 후 해당 bay CP-SAT 재실행 | Z1 |

- 수용: 엄격 개선(float, eps 1e-9 상대). 정체가 계측되면 record-to-record(임계 3%→0 선형)를 플래그로.
- 파괴 크기 k: `max(2, 3%·n)`에서 시작해 정체 시 확대(적응).
- **재시작/다변화**: 개선 없는 구간이 timelimit의 ~15%를 넘으면 incumbent를 교란(perturb)해 재출발. 큰 timelimit에서 지역 최적 탈출.
- 증분 objective(가이드): Z1 델타는 바뀐 블록 합, Z3 델타는 닫힌 식, Z2는 bay 수 ≤ 수 개라 전량 재계산 — 전부 float 정확. 권위는 항상 full check 값.

### 4.6 할당 초기화 (P1)

- v1(그리디): `w3·(S_i^max − S_ij)` + `w2`·Δrange 근사 + 혼잡 페널티(bay 부하율 `ρ_j = Σ area_i·P_i / (W_j·H_j·horizon)`가 임계 초과 시 w1 스케일 벌점)를 합산한 비용의 argmin으로 순차 배정, regret 순서.
- v2(게이트, CP-SAT): min `w3·Σ pen + w2·D`, `D ≥ ±(u_a·L_a − u_b·L_b)` 전 쌍, fit 행렬 하드 제약, 부하율 소프트 캡. n·m 이진 변수 수천 개 규모이며, 타임박스는 S4 게이트에서 실측으로 정한다.
- 정밀한 Z1 트레이드는 P3의 bay-move가 실측으로 담당한다(초기 할당은 출발점일 뿐).

### 4.7 인터락 densifier (S6, 게이트, 기본 off)

- 발동 조건: 비-인터락 최적화가 수렴한 뒤에도 tardy인 블록 존재 + 그 블록의 시간창에 공간이 없음이 확인될 때.
- 후보: guest(지각 블록)를 host들 위로 stagger — OBS 방향 판정(캐시), 진리표의 시간 제약(`a_host < a_guest`, `e_guest ≤ e_host`, 필요 시 host exit 연장 `≤ D_host` 우선), 제3자와의 쌍은 삼분법대로 독립 검사.
- 순이득 조건: `w1·(T_guest 감소) − w1·(T_host 증가) − (이후 배치 저해 추정) > 0`일 때만.
- 직렬화기 업그레이드 필수(§4.8). 진리표 단위 테스트 선행 필수.

### 4.8 Canonical serializer (단일 경로)

- 규칙: 날짜 오름차순, 같은 날짜 내 EXIT 전부 → ENTRY 전부.
- 같은 날짜·같은 bay에 EXIT ≥ 2: 비-인터락 해에서는 임의 순서가 안전(§2.4 갈래 2 정리)하므로 block_id 순. 인터락 해에서는 OBS 위상 순(guest 먼저); 구현은 "남은 present 중 `check_exit(fast=True)` 통과 블록부터"의 그리디 위상 정렬 + 실패 시 예외(수용 거부).
- ENTRY는 어떤 순서든 무방(같은 날 동시 진입이 합법인 조합은 union 서로소뿐이고 그 경우 순서 무관 — §2.4).
- operations dict 생성은 이 모듈 하나만 담당한다. 수제 조립 금지.

### 4.9 병렬 포트폴리오 (S5, 게이트, 기본 off)

- 1차 병렬화는 CP-SAT 내부 워커(안전)로 이미 확보. 2차: 3 워커 프로세스(seed/프로파일 상이) + 오케스트레이터, 주기적 best 교환. Linux fork 전제, join timeout, 워커 죽음 = 무시(전체는 단일 프로세스 결과로도 완결). 서버 유사 환경 측정에서 이득이 증명될 때만 on.

### 4.10 메모리·결정성

- 캐시 LRU 상한(판정 캐시 ~수백만 엔트리, 폴리곤은 (block,orient)당 1회). 16GB 한도 내 여유는 S0 메모리 계측으로 확인한다.
- 시드 고정. 병렬 off 상태에서 완전 재현 가능해야 테스트가 성립한다.

| **S3 LNS** | destroy-repair + retime 루프, anytime | 개선 곡선 단조; 300s 결과 ≥ 60s 결과(악화 0); 수용 카운트 > 0 구조 증거 |
| **S4 할당 정밀화** | bay-move/swap + v2 초기 할당 | 고-w2/w3 프로파일 인스턴스 부분집합에서 개선; 나머지 비회귀 |
| **S5 병렬 포트폴리오** | 프로세스 포트폴리오 (게이트) | 서버 유사 환경에서 wall-clock 이득 + 안정성(크래시 0) 증명 시에만 on |
| **S6 인터락 + 하드닝** | densifier(게이트) + 제출 패키징·스트레스·보고서 초안 | 밀집 부분집합 개선 시에만 on; 스트레스 매트릭스 전 항목 feasible |

시간이 부족하면 **S0–S3가 경쟁력의 본체**다. S4·S6은 인스턴스 프로파일에 따른 추가 점수, S5는 곱셈 요인.

## 6. 검증·측정 프로토콜

1. **계약 테스트**(S0, 구현 전 작성): §2.4 진리표 각 행, union-서로소 임의 순서 안전성, 같은 날 손바뀜 합법성, `P=0` 체류≥1, exit 연장 합법성+Z1 반영, obj2 float(내림 없음) 패리티 — 전부 합성 소형 인스턴스 + `check_feasibility` 오라클.
2. **패리티 테스트**: 내부 delta-objective vs 체커(±1e-6 상대); 표적 재검증 vs full check(무작위 후보 1,000건 판정 일치).
3. **벤치 매트릭스**: 전 훈련 인스턴스 × timelimit {10s, 60s, 300s}(주기적으로 1800s), 지표: feasible율(=100% 의무), objective, 단계별 시간, 수용/반복 카운트, retiming 이득, 캐시 적중률. 기존 baseline 실행 스크립트(`baseline/run_baseline_greedy.py`, `baseline/run_myalgorithm.py`)를 출발점으로 계측 러너를 만든다.
4. **개선 주장 규율**: 모든 개선 주장은 구조적 증거(수용 카운트, 단계별 시간)와 A/B(기능 플래그 on/off, 동일 커밋·동일 시드)를 동반한다. 재실행 잡음 대역 이내의 델타로 수용/기각하지 않는다.
5. **스트레스**: timelimit {0.5s, 2s, 5s}, bay 1개, 단일 레이어 인스턴스, 선호 bay에 물리적으로 안 들어가는 블록, 대형 n. 전부 feasible 반환이 통과 조건.
6. **제출 리허설**(S6): zip 루트 `myalgorithm.py`, 절대경로 없음, `utils.py` 무수정, 전 훈련 + 스트레스 인스턴스 격리 실행 all-feasible — 정의서 §5.1 체크리스트 전 항목.
